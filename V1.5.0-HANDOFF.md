## 1. What v1.5.0 adds

- New decks still build offline as `.apkg`.
- Imported decks are attached, audited, planned, applied, snapshotted, and reverted
  through **AnkiConnect only**.
- No raw SQLite writes, no `anki` Python library revision path, no MCP.
- If AnkiConnect is unreachable, `attach`, `audit`, `plan`, and `apply` fail with a
  clear setup message and nonzero exit. New `.apkg` generation remains offline.

### Quality constraints

The 98% heuristic floor outranks token, API-call, and speed savings. Do not trade
strong-model quality for weak-model reliability. Do not promote fuzzy or semantic
checks to hard gates without a known-good zero-warning corpus. Keep the review web
UI frozen: page, CSS, JS, Easy button, and summary text.

## 2. Current dossier schema

Location:

```text
${XDG_DATA_HOME:-~/.local/share}/anki-gen/decks/<deck-uuid>/
```

Key decisions:

- `schema: 1` is the initial public dossier schema. There is no earlier public
  format to migrate.
- `deck_uuid` is stable. `index.json` is a rebuildable cache, not authoritative.
- `cards.jsonl` holds authored identity/context.
- `anki_state.jsonl` holds note IDs, last-seen Anki fields, scheduling, revlog
  counts, and live/deleted/suspended state.
- `manifest.json` has format/schema/features, deck identity, a per-file
  role/schema/sha256/bytes table, counts, timestamps, migrations, and an open
  `extensions` map.
- Unknown fields are preserved under `extra`; unknown manifest metadata under
  `extensions`.
- A newer schema is refused for writes, never silently rewritten.
- Writes use a lock, staging tree, fsync, and atomic swap.
- `resources.jsonl` + `resources/` store arbitrary future files (media, datasets,
  notes, audio) with open `kind`/`role` strings.
- Context export is a deterministic, per-file checksummed archive. Unsafe paths,
  symlinks, duplicate entries, and oversized content are rejected.

### Layout

```text
decks/<deck-uuid>/
  manifest.json
  cards.jsonl
  anki_state.jsonl
  topics.jsonl
  style.md
  notation.json
  learner.md
  preferences.json
  decisions.md
  future_work.md
  deck_context.md

  source_excerpts.jsonl
  media_candidates.jsonl
  resources.jsonl
  resources/
  thumbnails/
  evidence/
  revisions/

```

## 3. Revision workflow

Commands:

```bash
revision.py attach --deck "NAME"
revision.py attach --deck "NAME" --reconstruct
revision.py audit --deck "NAME"
revision.py plan --deck "NAME" --intent "..."
revision.py apply --plan <plan.json> [--choice GROUP=delete|suspend|keep] ...
revision.py revert --deck "NAME" --last --yes
revision.py snapshots --deck "NAME"
```

Behavior:

- Plaintext intent is the interface; note IDs are internal.
- Plans write `revision_plan.md` and `revision_plan.json`.
- Manual Anki edits win by default; conflicts are reported.
- Destructive groups require an explicit Delete permanently / Suspend / Keep.
- Field-only updates preserve note/card IDs, scheduling fields, and revlog counts.
- Merge keeps the survivor's history; split keeps the existing card's history.
- New cards start new.
- Cloze ordinal changes require `--allow-card-shape-change`.
- Close Anki's Browser before field updates; apply requires `--browser-closed`.
- Sync is opt-in and only after verification.

## 4. Snapshots and revert

Current location:

```text
decks/<deck-uuid>/snapshots/<snapshot-id>/
  deck.apkg
  snapshot.json
```

Current behavior:

- Every apply takes an AnkiConnect `exportPackage` snapshot with scheduling before
  writing.
- Revert restores field updates, removes applied additions, restores deleted notes
  through `importPackage`, and restores suspension state.
- Manual edits after apply are preserved by default.
- A pre-revert snapshot makes the revert itself reversible.
- `snapshots/` is excluded from context export unless `--include-snapshots`.

### Planned adjustment: slim snapshots

Keep `deck.apkg`; reduce `snapshot.json` to metadata only:

```json
{
  "schema": 1,
  "snapshot_id": "...",
  "created_at": "...",
  "deck_key": "...",
  "deck": "SCHOOL::RTOS",
  "reason": "before apply",
  "apkg": "deck.apkg",
  "note_count": 142,
  "card_count": 168,
  "apply_log": "",
  "reverted_by": ""
}
```

Remove full `notes`, `cards`, and `revlog_counts` from the snapshot.

Put affected old state in `revisions/<stamp>/backup.json`:

- updated notes and old fields
- deleted notes and old fields
- suspended cards and old queue state
- affected dossier card/state rows only

`apply_log.json` already carries added note IDs and post-apply expected fields.
Revert should read `backup.json` + `apply_log.json`, not the full snapshot state.

Target shape:

```text
snapshots/<snapshot-id>/
  deck.apkg
  snapshot.json     # metadata only
```

### Planned adjustment: snapshot size and deletion

Keep every snapshot by default. Do not auto-delete. Add:

```bash
revision.py snapshots --deck "NAME" --sizes
revision.py snapshots --deck "NAME" --delete ID --yes
revision.py snapshots --deck "NAME" --prune --keep N --yes
```

- `--sizes` reports the deck UUID directory breakdown (snapshots, previews,
  revisions, resources) and warns above a configurable threshold.
- Warning text includes the deck UUID path and the exact delete command.
- Deleting a snapshot referenced by the latest apply log removes the easy revert;
  warn and require `--force`.
- Context export still excludes snapshots by default.
